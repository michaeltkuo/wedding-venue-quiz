What changed vs. the current embed, and why (click to expand)

The problem

The current embed-app.html is laid out like a full-width page: the intro and results heroes are full-bleed background-size: cover images about 420px tall with 72–76px headlines, and breakpoints use viewport @media queries. Inside a wide Squarespace block the photo turns into a thin cropped banner strip (Amy's QC notes: “weird half-page crop”, “banner image is squished”).

What this mockup does instead

  • Container-driven sizing. The card root has container-type: inline-size; every layout switch is an @container rule on the card's own width, so it behaves the same whether the block is a phone-width column or a narrow column on a desktop page.
  • Contained photo instead of a full-bleed banner. Photos are real <img> elements with object-fit: cover at a fixed aspect ratio (3:2 stacked on narrow cards, 4:5 beside the text at ≥ 640px). The photo can no longer be squashed into a strip, and no text sits on top of it, so no dark gradient is needed.
  • Fluid type. Headlines use clamp() with cqi units (intro headline about 30px at a 360px card, 56px at 1000px); padding and gaps scale the same way.
  • Layout steps: answers go 1 → 2 columns at 560px; buttons go full-width → inline at 460px; runners-up are compact thumbnail rows below 760px and three across above it.
  • Copy is Amy's approved wording. Match tag chips are left off the result on purpose (pending a decision). One runner-up (Villa Festa) has no review link, to show the “link only when a dedicated review exists” behavior.
  • Venue photos don't exist yet, so the existing FALLBACK_IMAGES are used. If an image fails to load, the neutral photo box keeps its size.

Open question: how should the Squarespace block size itself?

  • Grow to fit content (default here): the iframe height follows the card via the existing {type: "quiz-resize", height} message. No inner scrollbar, but the page height changes on every screen.
  • Fixed-height block (e.g. 640px): the page never jumps, but long screens (results, the 5-option questions on phones) scroll inside the block, which means a nested scrollbar on mobile.

Use the Height toggle above to compare. Both work with this card; nothing in the layout depends on the choice.

If approved: port the card CSS and markup into embed-app.html in a separate PR, keeping the existing question flow, API call, and resize message.
